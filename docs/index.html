01

Read-Only Media Librarian

Works OOTBstdio

The reference filesystem MCP server pointed at a media tree, mounted read-only, with no network.

“What's the largest file in my media folder and did anything land there this week?”

Stanza, env, scope

Upstream: Reference filesystem MCP server (modelcontextprotocol/servers)
Book: MCP for the Homelab, Chapter 4, Recipe 1

{ "mcpServers": { "media-librarian": {
    "command": "docker",
    "args": ["run", "--rm", "-i",
             "--network", "none",
             "-v", "${MEDIA_DIR:-/tank/media}:/media:ro",
             "mcp/filesystem:vX.Y.Z", "/media"] } } }
VariablePurpose
MEDIA_DIRoptionalDirectory on the Docker host to expose read-only as /media.
  • :ro mount: the server physically cannot write.
  • network_mode: none: nothing to phone home to.

Docker Forensics

Works OOTBstdio

docker-mcp scoped with ALLOW_LIST: the assistant sees and manages only the containers you name.

“Which containers have restarted more than once this week, and why?”

Stanza, env, scope

Upstream: Community docker-mcp server (pin your choice)
Book: MCP for the Homelab, Chapter 4, Recipe 2

{ "mcpServers": { "docker-forensics": {
    "command": "docker",
    "args": ["run", "--rm", "-i",
             "-v", "/var/run/docker.sock:/var/run/docker.sock",
             "--env-file", "<this folder>/.env",
             "docker-mcp:vX.Y.Z"] } } }
VariablePurpose
ALLOW_LISTrequiredComma-separated container names the assistant may see. This is the security boundary.
  • The only recipe that mounts the Docker socket.
  • ALLOW_LIST is the boundary; unlisted containers are invisible.
